# Как объяснить и продемонстрировать проект

## Краткое описание

Gadget Hub — учебный интернет-магазин. React рисует интерфейс и хранит временное
состояние, Go проверяет вход и обрабатывает заказы. Они работают на разных
локальных портах и обмениваются HTTP-запросами с JSON. Дизайн основан на
выданных макетах, компоненты — на UI kit.

## Демонстрация

1. Запустить проект и открыть главную. Показать баннер, обе карусели и их
   стрелки.
2. Перейти в каталог без входа: открывается страница логина.
3. Отправить пустую форму: поля подсвечиваются, запрос не отправляется.
4. Ввести неправильный пароль: сервер отвечает 401, появляется модальное
   сообщение.
5. Войти как `student` / `gadget123`. Показать изменённую шапку.
6. В каталоге показать сортировки, фильтры и страницы. Указать цену от 500000:
   появится пустая выдача. Сбросить фильтры.
7. Открыть робота и добавить одну штуку. Открыть часы Geozon Pink и добавить две
   штуки. Закрыть окно клавишей Esc.
8. Обновить страницу: количество осталось, потому что корзина в localStorage.
9. Открыть корзину: три единицы товаров, итог 31 990 ₽. Показать выбор
   чекбоксами и отмену удаления.
10. Отправить пустую форму оформления. Показать ошибки телефона и способа
    оплаты.
11. Выбрать доставку: появился адрес. Заполнить телефон и тестовый адрес,
    выбрать оплату. Email можно оставить пустым.
12. Оформить заказ. Показать сообщение об успехе, пустую корзину и запись в
    истории.
13. Открыть `backend/data/orders.json`: заказ сохранён на диске.
14. Выйти: каталог и корзина снова требуют входа.

## Почему корзина в браузере, а заказы на сервере

Корзина — ещё не оформленный выбор пользователя. ТЗ требует хранить её в
localStorage. В ней лежат только ID товаров и количества. Страница получает цены
из серверного каталога, а окончательную стоимость при оформлении повторно
рассчитывает Go.

Заказ — результат оформления, который должен переживать перезапуск браузера и
сервера. Поэтому он сохраняется в JSON на диске. При успешном ответе сервера
React удаляет запись корзины.

## Как кнопка на странице вызывает Go

Обработчик React собирает данные формы и выполняет `fetch('/api/orders', ...)`.
Vite в режиме разработки перенаправляет этот путь на порт 8080. Go ServeMux
выбирает обработчик по методу и пути. Обработчик проверяет cookie, разбирает
JSON, проверяет поля, рассчитывает итог и сохраняет заказ. Затем возвращает HTTP
201 и JSON. React показывает результат.

## Что такое сессия

После проверки логина и пароля сервер генерирует случайный токен. Браузер
получает его как HttpOnly cookie; JavaScript не читает значение. На сервере
токен связан с именем пользователя и сроком действия. Запрос к истории или
создание заказа без действующей сессии получает 401. Кнопка выхода отзывает
токен.

Проверка маршрутов в React управляет навигацией. Проверка на Go защищает данные:
обход интерфейса прямым запросом не открывает чужую историю и не позволяет
оформить заказ без входа.

## Фильтрация, сортировка, страницы

Полный каталог загружается с сервера один раз. На клиенте сначала применяются
фильтры, потом сортировка, затем выбираются девять элементов текущей страницы.
При изменении фильтра или сортировки открывается первая страница. Исходный
массив товаров не изменяется.

Черновик фильтров отделён от применённых значений. Поэтому переключение чекбокса
само по себе не меняет выдачу: требуется «Показать». Пустой список типов или
цветов означает отсутствие ограничения по этому признаку.

## Почему JSON вместо PostgreSQL

ТЗ разрешает файлы. Для небольшого локального проекта это уменьшает количество
инструментов и упрощает демонстрацию. Mutex защищает одновременное изменение
истории в одном процессе. Запись через временный файл не обрезает основной файл
во время подготовки нового содержимого. Для нескольких серверов и большого
количества пользователей понадобилось бы другое хранилище.

## Что можно показать в коде

- `state.jsx`: единое состояние корзины и синхронизация localStorage.
- `shop.js`: фильтры, сортировка и проверка полей.
- `components.jsx`: одна карточка и один контрол количества используются на
  нескольких экранах.
- `api.go`: маршруты, cookie и проверки доступа.
- `store.go`: серверный расчёт суммы и сохранение истории.
- Тесты: запрет отрицательных количеств и подмены итоговой цены, корректность
  фильтров, сохранение заказов.
