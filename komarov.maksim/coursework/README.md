# Gadget Hub

Курсовой проект по дисциплине «Web-разработка»: интернет-магазин гаджетов по
предоставленным макетам. Фронтенд — React и JavaScript, бэкенд — Go, данные —
JSON-файлы.

## Быстрый запуск

Требования к окружению: **Node.js 22.12+** (или 20.19+) с npm и **Go 1.24+**.

Команды выполняются из каталога проекта, содержащего папки `frontend`, `backend`
и этот README:

```bash
npm --prefix frontend install
npm run dev
```

Веб-интерфейс доступен по адресу **http://localhost:3000**, API —
**http://127.0.0.1:8080**. Остановка обоих серверов — `Ctrl+C`.

Учебная учётная запись:

| Логин     | Пароль      |
| --------- | ----------- |
| `student` | `gadget123` |

Регистрация не требуется: по ТЗ достаточно одного пользователя. После успешного
входа открывается главная страница. Каталог и корзина доступны только после
входа.

## Запуск в двух терминалах

Фронтенд и бэкенд также можно запускать независимо.

Терминал 1, из корня проекта:

```bash
cd backend
go run ./cmd/server
```

Терминал 2, из корня проекта:

```bash
npm --prefix frontend install
npm --prefix frontend run dev
```

Веб-интерфейс доступен по адресу http://localhost:3000. Vite перенаправляет
запросы `/api` на Go-сервер через dev proxy. Фронтенд и бэкенд работают в
отдельных процессах на разных портах. Настройки прокси находятся в
`frontend/vite.config.js`.

Проверка API: http://127.0.0.1:8080/api/health — ответ `{"status":"ok"}`.

## Что реализовано

- Главная: исходный рекламный баннер, закольцованные карусели хитов и новинок,
  преимущества, контакты.
- Вход: проверка пустых полей, сообщение о неправильных данных, серверная
  сессия, выход.
- Каталог: сетка из трёх колонок, фильтры по цене, типу и цвету, кнопки
  применения и сброса, пустая выдача.
- Сортировка по новизне, популярности и цене. Повторный клик по «Новые» и
  «Популярные» меняет направление сортировки.
- Пагинация по девять товаров. В полном каталоге 41 товар и пять страниц.
- Карточка товара в модальном окне: изображение, описание, характеристики,
  рейтинг, метки, цена и количество. Закрытие крестиком, Esc или кликом по
  затемнению.
- Корзина: общее состояние количества на всех экранах, сохранение в
  `localStorage`, одиночное и групповое удаление с подтверждением.
- Оформление заказа: телефон, необязательная почта, самовывоз/доставка, адрес
  при доставке, оплата, упаковка, проверка полей.
- Успешный заказ сохраняется на сервере; корзина и её запись в `localStorage`
  очищаются. При ошибке заказа корзина сохраняется.
- История заказов: номер, дата по московскому времени, количество и общая
  стоимость.
- Общие шапка и подвал, активный пункт меню, Rubik, состояния наведения/фокуса,
  ограничение длинных названий.

Интерфейс предназначен для настольных браузеров. Минимальная ширина страницы —
1100 px. Мобильная вёрстка не входит в требования проекта.

## Где хранятся данные

**Корзина:** в браузере, ключ `gadget-hub:cart:student`. Счётчик показывает
сумму количеств, а не число разных карточек. Корзина переживает обновление
страницы и выход/повторный вход. Пароль и токен сессии в localStorage не
записываются.

**Сессия:** случайный токен в HttpOnly cookie и запись на Go-сервере в памяти.
Срок действия — восемь часов. При перезапуске сервера потребуется войти снова.
Это не удаляет заказы или корзину.

**Каталог:** `backend`, загружается при запуске сервера. Изменения файла
применяются после перезапуска бэкенда. Цены, рейтинги, даты и описания
используются как демонстрационные данные для работы интерфейса; каталог не
является актуальным коммерческим предложением или проверенной базой
характеристик устройств.

**Заказы:** `backend`. Сервер рассчитывает сумму по своему каталогу и сохраняет
снимок названия, цены и количества. История не меняется от последующих изменений
каталога. Запись защищена mutex и выполняется через временный файл с последующей
заменой основного. Это учебное хранилище для одного экземпляра сервера;
одновременно запускать несколько серверов с одной папкой данных не следует.

Сброс истории выполняется при остановленном сервере заменой содержимого
`orders.json` на `[]`. Перед сбросом при необходимости сохраняется резервная
копия файла. Корзина очищается через интерфейс независимо от истории заказов.

## Настройки сервера

По умолчанию сервер запускается из папки `backend`. Доступны параметры:

```bash
go run ./cmd/server -addr 127.0.0.1:8080 -data data
```

Переменные окружения: `SHOP_USER`, `SHOP_PASSWORD`, `FRONTEND_ORIGINS`.
Последняя — разрешённые origin через запятую, по умолчанию
`http://localhost:3000,http://127.0.0.1:3000`. Значения считываются при запуске
сервера.

Авторизация рассчитана на локальную учебную демонстрацию. Реальные платежи,
регистрация, рассылки и админка не входят в проект. Выбор «По карте» только
сохраняет способ оплаты в заказе.

## Сборка и проверки

Из корня:

```bash
npm run build
npm run test:frontend
```

Из папки `backend`:

```bash
go test ./...
go vet ./...
```

При наличии C-компилятора можно дополнительно запустить `go test -race ./...`.

Сборка фронтенда сохраняется в `frontend/dist`. Собранная версия запускается
командой `npm --prefix frontend run preview` при работающем Go-сервере. Адрес
веб-интерфейса выводится в терминале. Режим разработки запускается командой
`npm run dev`.

## Если не запускается

| Симптом                                         | Решение                                                                |
| ----------------------------------------------- | ---------------------------------------------------------------------- |
| `go` или `npm` не найдены                       | Установить соответствующий инструмент, затем заново открыть терминал   |
| Версия Node не подходит Vite                    | Использовать Node 22.12+ или 20.19+                                    |
| Порт 3000 или 8080 занят                        | Остановить ранее запущенный экземпляр или другой процесс на этом порту |
| «Не удалось связаться с сервером»               | Проверить терминал бэкенда и `/api/health`                             |
| `data/goods.json` не найден                     | Запускать Go из `backend` или указать абсолютный путь через `-data`    |
| После перезапуска снова открылся вход           | Это ожидаемо: сессии в памяти, заказы на диске                         |
| Сайт не работает двойным кликом по `index.html` | Запустить серверы: приложению нужны маршруты, API и сборщик            |

Изображения и дизайн взяты из предоставленных учебных материалов. Rubik
распространяется по OFL; текст лицензии сохранён в
`frontend/public/assets/fonts/OFL.txt`. Иконки lucide-react — ISC. Ссылки на
соцсети ведут на общие страницы сервисов: адресов реальных аккаунтов магазина в
материалах нет.
